# アニメーション条件によるプリセット選択

状態: 本実装・自動テスト済み／実機受入確認待ち。以下は本実装の受入条件。

## 対象と条件

プレイヤー参加シーンのアニメーション名と、アニメーション全体のタグをプリセットの選択条件に使用する。名前とタグにそれぞれ正規表現を指定でき、空欄は制限なしとする。両方指定した場合は両方の条件を満たす必要がある。タグは取得順に半角スペース1個で連結した一覧全体に照合する。先頭・末尾に区切りを付けず、タグ0件は空文字列とする。照合は部分一致とし、大文字・小文字を区別しない。不正な正規表現はエラーを表示して保存を禁止する。

名前に`Billy`、タグに`^(?=.*\bsitting\b)(?!.*\bstanding\b).*$`を指定すると、名前にBillyを含み、sittingがありstandingがない場合だけ通過する。タグの順番を入れ替えてもこの条件の結果は同じ。取得成功した空のタグ一覧にはNOTだけの条件が一致し得るが、情報不明は条件付き候補を通過させない。

従来の個別タグ照合からの変更により、タグ欄の`^`と`$`は一覧全体の先頭・末尾を表す。単一タグの存在を判定する既存の`^sitting$`は、複数タグがある場合には`\bsitting\b`などへ変更する。

通常の初期選択とA/Dは、アニメーション条件と既存の可視性条件の両方を満たす候補を保存順で選ぶ。条件なしも同じ優先順位で扱う。条件不一致だけでは選択中プリセットを変更せず、既存のアンカー追従を維持する。編集用previewとデバッグの全件巡回は条件不一致によって禁止しない。

## 更新中の表示と選択

開始・変更・ステージ開始を受けた後、現在のアニメーション情報が確認できるまで、通常の初期選択・A/D・移動後の自動復帰を保留する。既に表示中のカメラは既存の所有権・移動制御の規則に従って維持する。保留中のA/D入力は後から再生しない。終了・ロード・所有権喪失の処理は保留しない。

変更通知だけでは、切り替え後の情報が取得可能になったと扱わない。ステージ開始またはアニメーション開始を受けた後に現在情報を確認する。通常のステージ進行でアニメーションIDが変わらなければ、確認済みの同一IDの名前・タグを再利用できる。

確認した情報と、それに対応する候補が揃った時点で選択を再開する。新しい情報と古い候補、古い情報と新しい候補を組み合わせて選択しない。途中で次の変更・開始・ステージ開始を受けた場合、前の更新では保留を解除しない。

移動完了だけではアニメーション情報を再取得しない。情報確認中なら移動後の評価を保留し、確認後の情報と移動後の位置で評価する。移動完了を理由に情報確認の保留を解除しない。

更新中にプリセットの保存・削除・Reloadが成功した場合、更新完了時には最新のプリセット一覧と条件を使用する。編集終了による明示的な選択維持は既存の仕様に従うが、それによって通常A/Dの保留を解除しない。

## 取得不能と終了

変更通知の後に開始・ステージ開始が届かない場合を含め、更新は最後に受けた対象通知から実時間5秒で打ち切る。取得失敗時も「情報不明」として確定する。情報不明では条件付きプリセットを候補から除外し、条件なしだけで選択を再開する。旧アニメーションの情報を現在情報として復活させない。選択中の構図は維持し、初期選択前なら条件なしの使用可能候補で初期選択する。候補がなければ通常カメラを維持する。

成功した空のタグ一覧は情報不明と区別する。次の開始・変更・ステージ開始で再度確認できる。一定間隔での再取得は行わない。

シーン終了・ロード・新規ゲームでは保持情報と保留中の更新を破棄する。同じシーン識別値が再利用されても、以前の取得応答を新しいシーンへ反映しない。別シーンの通知は現在シーンの更新状態を変更しない。

## 保証の境界

SSCが受信済みの対象通知より古い取得結果によって、新たな候補選択を行わない。通知受信と候補選択が重なる場合も、この順序を守る。

SLP+内部での変更とSSCへの通知の間まで完全に同期する保証は持たない。ステージ開始は姿勢同期完了を意味しない。対象環境でステージ開始から新しいアニメーションIDを取得できることは本実装の実機受入条件とする。不成立の場合はイベント連携を修正し、固定時間待ちやIDの二度読みだけを同期保証の代用にしない。

## 受入ケース

| 操作・順序 | 期待結果 |
| --- | --- |
| 初回開始、取得応答が遅い | 情報確定前に初期選択しない |
| Change、旧IDの応答、StageStart、新IDの応答 | 旧IDで候補を確定せず、新IDの条件で再開する |
| UI変更でStageStartのみ届く | 新IDの条件へ更新する |
| 通常のステージ進行で同じID | 同じ名前・タグを利用し、誤って別アニメーション扱いしない |
| Aの取得中にB、応答はB→Aの順 | Bだけを反映し、Aで候補も保留状態も変更しない |
| 応答処理待ちの間に変更通知を受信 | 応答の処理順が先でも古い候補を採用しない |
| 名前だけ成功、タグは未完了 | 完全な情報として公開せず保留する |
| 取得中に移動完了 | 最新情報と移動後の位置で評価してから復帰する |
| 取得中にプリセット編集・削除 | 最新の保存内容で候補を確定する |
| Changeのみ、または取得が応答しない | 最後の対象通知から5秒後に情報不明で再開する |
| 情報不明へ確定した後に遅い成功応答 | 確定結果を上書きしない |
| 取得中に終了・ロード、その後同一keyで再開始 | 古い応答を反映せず、新しい開始として取得する |
| 別シーンの変更・終了 | 現在の取得・選択に影響しない |

追加PoCは作成しない。取得PoCと専用計測は削除済み。調査記録は残す。
