# ロードマップ

## 現在の到達点

固定プリセットの読み込み、身体中心への平滑な追従、可視性に基づくA/D候補、Editor、Debug表示まで導入している。現在の期待動作は各設計文書に集約し、過去の開発段階で使った先頭固定カメラ・上空POC・可視性判定なしを現在の仕様として残さない。

| --- | --- | --- |
| シーン連携 | プレイヤー参加開始、変更待ち、終了、重複・別keyの採否 | [シーンカメラ手続き](scene-camera-procedure.md) |
| 外部連携 | 有効なP+入力、ロード前保留通知の無効化、ThirdPerson／Animated対応 | [Runtime](runtime-spec.md)、[カメラ更新との連携](hook-spec.md) |
| アンカー | プレイヤーの腰と胸の中間へ継続追従し、細かな揺れを抑制 | [アンカー](scene-anchor-design.md) |

## 検証状況

- 旧POCではAE 1.6.1170で、DLLロード、P+通知、SmoothCamの取得・上空構図・終了時復帰の主経路をゲーム内確認した。上空構図は削除済みであり、現在のテストの対象ではない。
- キャラクターcollisionの透過と、壁・家具による候補除外は一部のゲーム内ログで確認した。すべての場所・人数・collisionの重なりを保証したものではない。
- 最新の追加調査では、thread IDの範囲判定を修正し21ケースを追加した。`build.cmd`でDLL・4テスト群・DLL検査が成功している。
- 現行のEditor、入力競合、ポーズ中の復帰、対応外カメラ状態、通知側の復帰とSmoothCamの実行順は、必要な組み合わせのゲーム内確認が残る。
- 検証対象と文書間の対応は[考慮漏れ検知](spec-coverage.md)、追加調査の根拠は[調査記録](spec-investigation.md)で追跡する。

## 次に確認すること

1. 通常・Debug・Editorそれぞれで、終了・ロード・reset・所有権喪失後の復帰を確認する。
2. 一致しないkeyの通知と終了済み対象への重複終了が、現在のカメラを変えないことを確認する。同一key再利用後の旧通知識別は現在の保証に含めない。
3. アニメーション変更から1秒の待機で、新しい姿勢が実用上いつ反映されるかを確認する。この待機は同期完了の保証ではない。
4. 寝姿勢を含む追従で、細かな揺れが減り、ゆっくりした動きが残るかを確認する。
5. 壁際、狭い室内、多人数、極端な身長差で、現在のプリセットと可視性条件による表示を評価する。
6. 保存件数を増やしたときの評価時間を計測し、利用可能なプリセット数と性能上の制限が必要か判断する。

## 現在の制限

- 実時間30分超でシーンを終了し、ポーズとEditor中の時間も含める。Startingだけの準備状態にはこの上限を適用しない。上限を変更する場合は手続き仕様から更新する。
- 同一scene keyの再利用後に届く旧通知、新しいEditorを開いた後に届く過去の画面終了を、それぞれ過去の対象専用として除外する保証はない。
- VR、Improved Camera、既存カメラ連携を遮断する後発Modは対応対象外とする。
- シーン途中の参加者構成変更と、StageStartを独立した更新境界として扱うことは対象外とする。
- アンカーが環境collision内にある場合の位置補正、候補までの移動経路、キャラクター同士の画面上の重なりは現在の可視性評価に含めない。
- キャラクターcollisionと薄い環境collisionがほぼ同じ位置で重なる境界は、判定保証を行わない。

## 将来の検討

次は未採用の案であり、現在の確認ケースの期待結果にはしない。

- プリセット間の位置・回転・FOV補間を追加するか決める。移動させる場合は経路の安全性も定義する。
- 継続的なカメラ演出の方向とタイミングを検討する。単純なYaw往復は採用しない。
- 壁・家具付近で候補位置を補正するか、使用可能な領域を求めるかを検討する。
- プリセット評価が時間予算を超える場合は件数上限や評価の分散を検討する。
- 相手による遮蔽への対処としてP+の透明化機能を利用する案は、外部契約・利用可否・復帰保証を確認してから採否を決める。
- 次回起動の選択記憶、scene外の数値編集、IDと表示名の分離、gamepadの細かな調整は、利用要件に応じて別途仕様化する。
