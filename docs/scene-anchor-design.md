# シーンアンカー

状態: **胴体中央への平滑な追従を仕様化／追従の強さは実機調整待ち**

## 定義

シーンアンカーは、現在のアニメーションに対する撮影基準である。カメラプリセットの相対位置と相対回転をワールド座標へ変換する基準であり、カメラ側の中心・四隅からのLOSの終点にもなる。

## 要件

- 現在のシーンを代表する位置と向きを持つ。
- カメラプリセットの相対座標系として使える。
- プレイヤーの正面側と背面側を区別できる。
- カメラ側の中心・四隅からのLOSの終点として有効である。
- プレイヤーの姿勢と移動に継続して追従する。
- 一時的に入力を取得できない場合に不連続な移動を起こさない。

## 計算仕様

プレイヤーの現在の姿勢における腰と胸の中間を胴体中央（本書での身体中心）とし、アンカー位置の追従目標に使う。中間は高さだけでなく前後・左右も含む。他の参加者の3D有無、骨格、位置はアンカーの成否および位置へ影響させない。可視性判定は平滑化後のアンカーへのLOSとし、詳細は可視性評価の設計に従う。

```text
anchorTargetPosition = (playerWaistPosition + playerChestPosition) / 2
```

アンカーの向きは参加者の配置や骨格に依存させず、プレイヤーActorの水平前方の逆向きとする。

```text
anchorForward = -normalize(playerActorForward)
```

この向きは参加人数や、アンカー位置に対してプレイヤーがどちら側にいるかに依存しない。プレイヤーが他の参加者へ正面を向けている場合と背中を向けている場合でanchor forwardが反転するため、同じorbit yawでプレイヤーの表裏を一貫して表せる。

プレイヤーActorを取得できない場合、腰または胸の位置が有効でない場合、または有効な水平前方を得られない場合は、新しいアンカーを生成しない。腰だけ、胸だけ、または外形の中心へ代替しない。

現在のcamera orbit規約ではYaw `0`のcameraをanchor forwardの反対側へ置く。このため、このanchor定義ではYaw `0`がプレイヤー正面側、Yaw `±180`がプレイヤー背面側になる。

この計算結果が static collision 内にある場合の補正またはフォールバックは、別途検討する。

## ライフサイクル

```text
シーン開始
  -> 有効な身体中心を取得できるまでカメラを取得せず再試行
  -> 取得できた身体中心から最初のアンカーを計算

シーン継続中
  -> 現在の身体中心からアンカーを更新
  -> 一時的に取得できない場合は直前の有効なアンカーを維持

アニメーション変更
  -> アンカー追従は継続
  -> AnimationChange通知後、有効な入力を得られる最初の更新でプリセット候補とraycast結果を再評価

シーン終了
  -> アンカーを破棄
```

アンカー位置は胴体中央へ滑らかに追従し、細かな揺れを抑えながら、ゆっくりした身体の動きは残す。目標が静止した場合、位置の差は0.15秒で半分、約0.5秒で約10%になる。同じ経過時間ならフレームレートによらず同等の追従量とし、目標を行き過ぎない。初回は胴体中央へ直接合わせ、前のシーンの位置から移動させない。向きは従来どおりActorの水平前方から定まり、平滑化の対象にしない。

ポーズ中は追従を進めず、ポーズ時間を再開時の追従量へ加えない。入力欠落中は直前のアンカーを維持し、復帰後は現在の目標へ滑らかな追従を再開する。アニメーション変更でも追従は継続し、再評価を理由に位置を飛ばさない。

P+の`AnimationChange`は変更開始時の通知であり、変更後の姿勢が利用可能になったことを保証しない。候補と可視性は通知後、有効な入力を得られる最初の更新で再評価する。同じ更新までの変更通知は一度の再評価にまとめる。姿勢の同期完了を固定時間で推定せず、その後もアンカー追従と定期評価を継続する。

## 確認項目

- 立位、座位、寝姿勢で、アンカーが現在の腰と胸の中間へ滑らかに追従し、静止後はその位置へ収束する。
- 腰と胸の高さが同じ寝姿勢でも、前後・左右を含めた中間になる。
- 腰と胸の位置が同じなら、装備の外形や相手の骨格・位置が変わってもアンカー位置は変わらない。
- 腰または胸を取得できない場合、開始前は再試行し、追従中は直前の有効なアンカーを維持する。
- デバッグモードのアンカーマーカーで胴体中央への追従を確認できる。
- 目標が静止した場合、0.15秒後の位置の差が元の半分になる。30 FPSと144 FPSでも同じ経過時間で同等の位置に到達する。
- ポーズ中および入力欠落中は位置を維持し、再開後に待機時間分を一度に追従しない。
- 終了、ロード、reset後に別シーンの位置を引き継がない。

## 現時点で扱わないもの

- stage を独立した更新境界として扱うこと。
- static collision 内に計算されたアンカーの補正またはフォールバック。

これらは実際に問題が確認された時点で検討する。
