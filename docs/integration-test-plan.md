# 手動回帰を減らす結合テスト計画

## 方針

製品コードにテスト専用分岐、公開メソッド、friend、同期フックを追加しない。テストダブルとシナリオ補助は`tests/`以下へ置き、既存の依存注入だけを使う。

SceneCamera、AnimationUpdateCoordinator、PresetFilterEvaluator、候補選択、MainUpdateDispatcher、PresetRepositoryは本物を使用する。外部のメタデータ応答、身体・入力状態、物理判定、カメラ出力、時計だけを置き換える。保存とReloadは各ケース専用の一時ファイルで実行する。

## 追加範囲

- 名前・タグ・情報不明の組合せから初期選択とA/Dまで。
- 肯定・否定先読み、保存順、汎用候補、可視性とのAND、現在選択の維持。
- 保存・実ファイルReload・不正入力・読込失敗から候補更新まで。
- Dispatcherでの処理待ち、取得待ち、候補評価中の通知・保存・削除。
- 既存のタイムアウト、旧応答、終了・ロード相当reset、移動保留テストの再利用。
- 実際の並行処理の確認が必要な受信と公開の境界は、テスト側の物理判定ダブルに同期点を置く。sleepや偶然のタイミングには依存しない。ゲーム本体が直列配信する通知同士の順序は入れ替えない。

## 完了条件

build.cmdで既存・追加テストが成功し、失敗時にはシナリオ名と期待結果が分かる。手動回帰表へ自動テストとの対応を記載し、代替した判定条件と実機に残る確認を区別する。

P+の実通知・VM、SmoothCamとFOV、実物理判定、Editorの表示・入力・ポーズ・ボタン操作は実機に残す。RepositoryのSave成功をEditorのボタン確認の代用にはしない。

## 実施結果（2026-09-14）

- `tests/support/SceneCameraDoubles.h`へ既存ダブルを集約し、`tests/AnimationFilterIntegrationTests.cpp`へ7シナリオを追加した。製品コードへの変更はない。
- 名前・タグの条件表は8組。保存とReloadは実ファイルを使い、並行受信はテスト側の同期点で再現する。待ちには異常時のタイムアウトを設ける。
- `build.cmd`で全4スイート成功。実機で必要な確認は[手動回帰テスト](regression-manual-test.md)に記載した。
