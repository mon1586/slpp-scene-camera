## 操作手順

2026-09-11の修正版ログで、短い移動後の自動復帰、約39秒の時間切れまでの返却維持、通常シーン終了後の解放を確認した。最初の修正版テストに対するユーザー報告は「問題なさそう」。両ログとも移動中のプリセットcut・構図反映は0回、error/criticalも0件。

時間切れの回は移動後に有効プリセットがなく、再評価後も通常カメラを維持した。後の再取得はEditorを開いた時であり、自動復帰成功とは区別する。候補なし時の処理は仕様通り。以下の追加ケースまで全て実ゲームで確認したという意味ではない。

最初はSSCのDebug OFF、Editorを閉じた状態、SexLabの自動TFC OFFで行う。各ケースの開始時刻をおおよそで控える。手順にない設定変更をした場合は、その内容も残す。

1. プレイヤー参加の移動可能なシーンを開始し、SSCの構図が表示されてから5秒待つ。
2. Move Sceneに入り、移動と視点操作を試す。A/Dで横移動しても構図が切り替わらないことを確認する。ホットキー長押しで終了し、移動先でアニメーションとSSCカメラが再開するか確認する。
3. 同じシーンでもう一度Move Sceneに入り、時間切れを待って同じ項目を確認する。診断版では長い区間が約39秒だったので、実時間30秒ちょうどで終了するとは扱わない。
4. 通常どおりシーンを終了して5秒待ち、視点・移動・FOVに異常が残らないことを確認する。

移動が再制限され、対応カメラ状態かつ非ポーズで、返却完了と有効な身体情報を確認できた最初の更新で復帰を試みる。再配置通知を理由に固定時間を待たない。有効な構図がない場所では取得せず、通常カメラを維持する。戻らない場合は無理に操作を重ねず、場所と状況を報告する。

## 残る受入ケース

主経路の確認後、次のケースも確認する。操作できないケースは「未実施／操作不可」と記録し、成功扱いにしない。

- 説明画面の取消、再配置不可の画面での取消が表示される場合、シーンカメラが正常に継続・復帰すること。移動中に任意キャンセルできることは前提にしない。
- Move Scene中にシーン終了操作が可能なら、終了後にSSCへ再取得しないこと。
- Move Scene中に保存済みゲームをロードし、旧シーンの復帰が残留しないこと。
- Debug ONではMove Scene前後とも独自カメラを取得せず、設定を維持すること。
- Editor中に遅延した移動許可が到着する状況を再現できる場合、previewと編集操作をロックし、返却を未保存確認で妨げないこと。この競合は自動テスト済みだが、ゲーム内での成立・表示は未確認。

reset、返却失敗、入力状態取得不能、別シーンの通知等は自動テストで検証済み。外部APIの実際の失敗やスレッド条件をゲーム内で再現したという意味ではない。

## 解析と次の段階

`MoveScene probe v1 callback` と `MoveScene probe v1 state` を既存の開始・終了・SmoothCam取得／返却ログに重ねる。stateの1は許可／有効、0は不許可／無効。cameraの-1は取得不能、それ以外はゲームのCameraState ID。sscReportedOwnerはSSC内部の所有フラグであり、外部Modの実所有者の保証ではない。worldFOVは状態変化時だけの標本。

`Scene camera suspended` → SmoothCam返却 → `resume queued` → 新しいanchor取得 → SmoothCam再取得の順を確認する。移動中にプリセットcutやSSCの構図反映がないこと、シーン終了後に再取得がないことも確認する。不具合があれば修正し、関連する自動テストとゲーム内ケースを再実行する。
