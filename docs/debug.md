# 可視性評価のデバッグ表示

状態: **設定可能な診断モードを実装・自動テスト・DLLビルド済み／実機確認待ち**

## 目的

カメラ側の中心・四隅からアンカーまでの可視判定と、遮蔽物へのhit位置がゲーム画面上の状況と一致することを確認できるようにする。

## 詳細設計

- Preset dashboardに`Debug mode`を表示し、初期値はOFFとする。変更した状態は再起動後も維持する。
- デバッグ表示を利用できない場合は設定操作を無効にして理由を示し、保存値がONでも通常のシーンカメラを妨げない。
- デバッグモードがONの間は独自のカメラ制御を取得せず、SmoothCamの表示を維持する。
- 通常のプレイヤー参加シーンと同じ契機で全プリセットを評価し、選択中の1件について候補位置と可視判定結果を表示する。
- active scene中は`A` / `D`で、最新の使用可能候補だけを保存順の前後へ循環してデバッグ表示を切り替える。実際のカメラは変更しない。現在の表示対象が使用不能になっても自動では変更しない。scene外の入力は保持しない。
- 評価済みのワールド座標を、ゲーム画面上で線と点として確認できるようにする。
- 選択中プリセットの候補位置を、rayの始点として識別できるマーカーとプリセットIDで表示する。
- 緑線は評価点まで見える経路、赤線は遮蔽物へ到達した経路、灰色線はhit位置から本来の評価点までを表す。
- アンカーと、遮蔽物へのhit位置を区別できるマーカーで表示する。
- hit面の向きを確認できるよう、hit位置から法線を表示する。
- 遮蔽物へのhitから本来の評価点までの参考区間を、表示または非表示にできるようにする。
- アンカーは、画面へ投影した位置とforward方向を、rayと同じHUD表示上の点と線で表す。ゲーム世界へデバッグ用オブジェクトを配置しない。
- 水色の`Anchor`は平滑化後の撮影基準を、オレンジ色の`Torso target`は補正前の腰と胸の中間を示す。二つの位置を比較して揺れの抑制と追従の遅れを確認できる。5本のLOSはすべて水色のアンカーへ集まる。
- デバッグモードをOFFにした場合は表示を消し、active scene中なら保持しているプリセットのカメラ制御を再開する。選択がない場合は通常カメラを維持する。
- OFFへの復帰で取得を一時拒否された場合は、実時間で0.5秒以上間隔を空け、最初の試行を含め最大3回、OFF操作から2秒以内に限り再試行する。他Modが所有するカメラを強制解放しない。
- 取得できないまま上限に達した場合は再試行を終了し、復帰できなかったことを表示する。再度のON/OFF操作で改めて復帰を要求できる。
- 再試行は直前の試行から実時間0.5秒ちょうどで実行可能になる。OFF操作から2秒ちょうどでは期限切れとして新たな取得を行わない。同じOFF状態の再通知では回数・期限を更新しない。
- 復帰に必要なアンカー入力が欠落している間は取得を試さず、試行回数を消費しない。ただし2秒の期限は延長しない。期限内に入力が復帰すれば必要な候補評価後に試行し、期限に達してから復帰しても古い要求では取得しない。
- その更新でONへの変更、編集開始、終了、reset、または期限切れが確認された場合は、保留中の復帰試行より取消を優先する。取得済みの後でONや終了が届く場合は、それぞれの通常の解放規則に従う。
- ポーズ中は追従と定期候補評価を進めない。ただし設定切り替え時のカメラ解放と上記の復帰処理はポーズ中も進める。再試行のたびに全候補を評価し直さない。ONへの変更、編集開始、シーン終了、resetで未完了の取得再試行を取り消す。
- 判定時に保存した結果を描画とログで共有し、デバッグ表示のために判定を再実行しない。
- シーン終了、再評価、ロード、新規ゲーム、reset時に古い表示データを破棄する。

## アンカーLOSの定期計測

- 通常・デバッグモードのプレイヤー参加シーンでは、ポーズ時間を除く0.5秒ごとに、全保存プリセットのカメラ側に置いた長方形の四隅と中心から、平滑化後のアンカーの一点へのLOSを再評価する。一候補あたり5本とする。
- 長方形はゲーム内単位で幅32・高さ18（16:9）の固定サイズとする。中心は候補カメラ位置に一致し、横と縦は各候補カメラから見た右方向と上方向に揃える。カメラ距離、FOV、画面解像度でサイズを変えない。5本の経路はアンカーへ向かうほど狭まり、身体の周囲へ判定範囲を広げない。
- 中心のLOS成否と、四隅の通過数（0〜4）を分けて表示する。使用可能条件は中心可視かつ四隅3本以上可視とし、判定不能な点がある場合は使用不能とする。
- 各回の候補位置と終点は、その回の同じアンカーに基づく。判定結果と表示する線は同じ評価時点の座標を使う。
- デバッグの四隅のラベルはカメラ側の始点に表示し、5本が同じアンカーへ集まることを確認できる。
- プレイヤー自身を含むキャラクターのcollisionを透過し、壁や家具など環境の遮蔽物を調べる。アンカーがプレイヤーの体内にあることを理由に遮蔽とはしない。これは身体部位そのものの可視性やNPCによる遮蔽を評価するものではない。
- 定期評価の結果を通常モード・デバッグモードのA/D候補一覧へ反映する。結果による自動切り替えや通常カメラへの復帰は行わない。
- 全候補を毎回評価し、選択した一件のアンカーLOSを表示する。`A` / `D`で選択した候補は定期更新後も維持する。選択した候補が削除された場合は先頭の候補を表示する。
- 画面には評価間隔、計測回数、候補数、直近の評価時間、平均・最大評価時間、直近のLOS処理時間、キャラクター透過分を含む実際の物理ray数を表示する。平均評価時間から求めた1秒当たりの処理時間も表示する。
- 評価時間は候補位置生成、LOS問い合わせ、結果の構築を含み、ログ出力とHUD描画の時間を含まない。LOS処理時間は問い合わせ全体の時間であり、純粋な物理エンジン内部の時間ではない。
- 詳細ログは最初の計測と以後10回ごとに集計を出す。CPU全体の使用率や描画負荷は、この計測値だけで判断しない。
- ポーズ中、編集中、アンカー入力欠落中、シーン外、アニメーション変更後の再評価待ちでは定期再評価しない。通常モードでも同じ0.5秒周期で候補を更新する。遅れた更新の回数分を一度に実行せず、1更新あたり最大1回とする。変更後評価と定期評価が重なる場合は変更後評価を一度行い、そこから定期評価の間隔を数え直す。
- デバッグモードOFF、シーン終了、ロード、resetで周期と集計を破棄する。

## 可視性評価ログ

デバッグモードの集計ログには、候補数、中心と四隅の可視数、実際の物理ray query数と所要時間を表示する。個別の経路とhit位置は保存済みの結果を画面で確認できる。

## 対象外

- 可視判定とは別の問い合わせを使った表示結果の再計算。

## 確認項目

- デバッグモードをONにすると、取得済みのカメラ制御を解放し、SmoothCam表示へ戻る。
- デバッグモード中はカメラ制御を取得せず、候補位置、ray、身体中心、hit情報、アンカーだけを表示する。
- `A` / `D`で使用可能プリセットを循環してもカメラ位置は変わらない。
- アンカーの位置とforwardをrayと同じHUD上で確認でき、ゲーム世界にデバッグ用オブジェクトが残らない。
- デバッグモードをOFFにすると表示が消え、保持しているプリセットへ復帰する。取得が拒否された場合は上限内で再試行し、選択がない場合は通常カメラを維持する。
- 保存したデバッグモード設定が再起動後も維持される。
- 見える経路、遮蔽物までの経路、遮蔽物から評価点までの経路を、それぞれ緑、赤、灰色で識別できる。
- 身体中心とhit位置を、異なるマーカーで識別できる。
- hit位置から法線の向きを確認できる。
- 選択中プリセットの候補位置とIDを識別できる。
- hitから本来の評価点までの参考区間を表示する状態と表示しない状態を切り替えられる。
- 中心と四隅の表示結果が使用可否と一致する。
- 集計ログのray query数が、キャラクターのcollisionを透過するために追加で行った問い合わせを含む。
- シーン終了、再評価、ロード、新規ゲーム、reset後に古い線と点が残らない。
- 0.5秒未満では定期LOSを実行せず、経過後に有効な各保存プリセットのカメラ側の中心と四隅から現在のアンカーへ合計5本ずつ問い合わせる。
- 5本の終点はすべて同じアンカー位置になり、アンカー付近に四隅の終点を置かない。
- カメラのyaw・pitchが変わると長方形もそのカメラの右・上方向に揃い、幅32・高さ18は変わらない。
- 中心だけ遮られた場合と四隅の一部だけ遮られた場合を区別できる。
- LOSが通らない候補や問い合わせ失敗が発生しても、定期計測によってカメラ制御を取得・解放・切り替えしない。
- デバッグを終了した後も、通常のA/D候補選択は同じ5本LOSの条件を使う。
