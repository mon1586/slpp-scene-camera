# アーキテクチャ

## 全体構成

コードは `src`、`runtime`、`core` の3つに分ける。

依存方向は次の2本だけとする。

```text
src -> runtime
src -> core
```

`runtime` と `core` は互いに依存しない。`runtime` と `core` から `src` にも依存しない。

`src` は手続きを進める層である。`runtime` との間で開始、更新、終了などの通知と入出力をやり取りし、その過程で必要な機能を `core` から呼び出す。

エントリーポイントは依存を組み立てるbootstrap境界に限定する。外部イベントの解釈やライフサイクル処理は`runtime`へ委譲し、手続き上の判断は持たない。

## 責務

### src

- 処理全体の順序と状態を持つ。
- `runtime` から開始、更新、終了の通知を受け取る。
- 処理に必要な入力を `runtime` へ要求する。
- 必要な機能を順番に `core` から呼び出す。
- Coreの結果を次の処理へ渡し、必要なら `runtime` へ出力する。
- 終了通知を受けたら処理を終了し、必要な終了処理を `runtime` へ伝える。
- ゲームや外部ModのAPI詳細、および個々の計算ロジックは持たない。

### runtime

- ゲーム、SKSE、外部Modとの接続を担当する。
- 外部イベントを受け取り、`src` が扱える通知と入力へ変換する。
- `src` から要求されたゲーム状態を取得する。
- `src` から渡された結果や終了処理をゲームと外部Modへ反映する。
- 処理の順序や機能上の判断は持たない。

外部イベントと入出力の具体的な契約は[`runtime-spec.md`](runtime-spec.md)に記載する。

### core

- 個別の機能と計算を提供する。
- 同じ入力に対して再現可能な結果を返す。
- 手続きの順序、ゲーム状態、イベント、外部Mod APIを知らない。
- `src` と `runtime` には依存しない。
