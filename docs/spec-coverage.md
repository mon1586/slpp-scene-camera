# 仕様の考慮漏れ検知

作成日・更新日: 2026-09-06。状態: **追加調査を反映し文書の不整合を整理済み／thread ID境界修正・21ケース追加／実機確認は未実施**。

## 目的と使い方

条件の組み合わせ、状態ごとのイベント、順序・中断、常に守る性質を別々に確認し、仕様の空欄と文書間の不整合を検出する。本書は既存仕様を横断する確認台帳であり、新しい動作を暗黙に決定しない。内部クラス、処理方式、APIの呼び出し方は定めない。

1. 変更対象の仕様と、その変更で増減する状態・イベント・条件を確認する。
2. 状態×イベント表の該当セルと、モードを重ねた場合の期待結果を確認する。
3. 条件分岐をディシジョンテーブルへ、順序に依存する動作を時系列ケースへ追加する。
4. 不変条件と境界値で、正常系以外の結果も確認する。
5. 未定義・矛盾を未決事項へ登録する。解決時は担当する設計文書を先に変更し、本書とテストの期待結果を追従させる。

空欄は使わず、各セルを「動作」「無視」「前提外」「未定義」「要整合」のいずれかで記録する。「前提外」は届いた入力を無視してよいという意味ではない。根拠のない例外扱いで網羅率を上げない。

本書での「既定」はdocsに期待動作があることを意味し、実装済み・テスト成功を意味しない。テストに落とす際は、前提、入力の順序と時刻、期待する選択・カメラ所有・FOV・編集可否・保存内容、確認結果を記録する。

## 状態とイベントの棚卸し

### シーンの基本状態

以下は仕様を確認するための状態名であり、実装の状態名を要求しない。

| 状態 | 定義 | 主な出口 |
| --- | --- | --- |
| S0 対象なし | activeな対象シーンがない | 有効なプレイヤー参加開始 |
| S1 開始準備 | 開始準備を受理し、初回アニメーション開始を待つ | AnimationStart、終了、reset |
| S2 初期入力待ち | AnimationStart後、有効なアンカー入力をまだ取得できない | 入力取得成功、終了、reset |
| S3 選択なし | アンカーはあるが、通常表示するプリセットがない | A/D、編集開始、終了、reset |
| S4 選択あり | 通常表示またはデバッグ対象の選択を持つ | A/D、編集、終了、reset、所有権喪失 |
| S5 復帰待ち | 終了・resetを受理したがカメラ解放がまだ完了していない | 解放成功後S0へ |

基本状態だけで全状態を表したことにしない。次の軸を重ねて確認する。

| 軸 | 値 | 組み合わせ時の注意 |
| --- | --- | --- |
| モード | 通常／Debug | Debug中の選択はカメラ所有を意味しない |
| 画面 | 閉じている／Dashboard／Editor／確認待ち／編集ロック | Dashboardの選択と実際の構図の選択を分ける |
| 時間 | 0.5秒・1秒・2秒・30分の直前／一致／直後、長いポーズ、長い更新間隔 | 定期評価はポーズ除外、変更待ち・Debug復帰・30分上限は実時間。一致条件はPROC・DBG |
| 再評価 | 予約なし／変更後の1秒待ち／定期評価期限 | 同じ更新で期限が重なる場合も確認する |
| 身体入力 | 有効／初回から欠落／取得済み後に欠落 | 初期取得待ちと、直前の構図維持を分ける |
| カメラ | 未取得／所有中／取得拒否／所有権喪失 | 拒否と喪失を同じ復帰条件にしない |
| プリセット | 保存0件／使用可能0件／1件／複数件／選択ID削除済み | 保存0件と一時的な遮蔽を分ける |
| 編集内容 | 保存済み／未保存／最新値のpreview未確認／保存失敗 | 画面にある値を保存可能とみなさない |
| 機能の利用可否 | 利用可能／初回有効化失敗／依存機能なし／非サポート構成 | UIが使えない場合とカメラが使えない場合を分ける |

最低限、通常・Debug・Editorそれぞれについて、終了、reset、入力欠落、所有権喪失を確認する。全軸の直積を無条件に作る必要はないが、省略する組み合わせには理由を残す。高影響の中断ケースは組み合わせテストの削減対象にしない。

### モード・操作・中断の重ね合わせ

S5ではモード・画面にかかわらず次の規則を優先する。

| 入力・条件 | 復帰待ちでの動作 |
| --- | --- |
| 更新、ポーズ中の更新、通知処理の機会 | まず解放を再試行。失敗が続く間は評価・追従・構図反映・取得を行わない |
| 開始・変更通知 | 解放が完了しない間は受理せず、後から再生するためにも保持しない。解放が完了した後はS0の採否に従う |
| A/D、旧preview、未完了のDebug復帰 | 取り消し済み。旧シーンの処理を再開しない |
| 終了・resetの再通知 | 復帰待ちを維持し、解放成功を偽らない |
| 処理済みresetの遅延した実行機会 | 新しいreset要求がなければ何もしない。新シーンを終了させない |

### D4 Debug OFF後の復帰

| 規則 | 条件 | 期待結果 | 根拠 |
| --- | --- | --- | --- |
| D4-1 | 選択なし | 通常カメラを維持 | DBG |
| D4-2 | 選択あり、取得成功 | 保持しているプリセットへ復帰 | DBG |

## 不変条件

個別イベントの期待結果が合っていても、次の性質を破っていれば不合格とする。根拠に矛盾がある場合は、その部分の判定を保留する。

| ID | 常に守る性質 | 根拠 |
| --- | --- | --- |
| I01 | 別keyの開始・変更・終了は現在の対象を置換・解除しない。準備中の同一keyのStartでプレイヤー不参加なら準備を取り消す | PROC |
| I02 | 有効な構図とFOVを準備する前にカメラを取得しない。所有権喪失後は反映を続けない | RT、FILE |
| I03 | 所有中の解放ではFOV offsetを解除する。未取得時の解放要求で外部状態を変更しない | RT、UI |
| I04 | 終了・ロード・reset後に前シーンのアンカー、候補、表示を使用しない | ANCHOR、VIS、DBG |
| I05 | Debug中は独自カメラ制御を取得せず、診断表示の失敗で通常機能を妨げない | DBG |
| I06 | 可視性の悪化だけで現在の選択を切り替えたり解放したりしない | VIS |
| I07 | 入力欠落中は前の構図を維持し、古い評価によるA/D切り替えを行わない | ANCHOR、VIS |
| I08 | Dashboardを閲覧・選択するだけではカメラとゲーム時間を変更しない | UI |
| I09 | 未確認のpreview値を保存せず、保存・読込失敗で正常な保存データを失わない | UI、CRUD |
| I10 | 通常の編集終了では未保存変更の確認を行い、安全境界では確認待ちが復帰を妨げない | UI |

## 時系列ケースと仕様の対応

## 継続運用と完了判定

仕様の変更ごとに、次の記録を残す。

| 項目 | 記録する内容 |
| --- | --- |
| 仕様 | 担当文書の節、変更した期待動作 |
| 影響範囲 | S・E・D・I・T・Gの該当ID、追加したモードの組み合わせ |
| 判定 | 既定／未定義／要整合／前提外、根拠 |
| 検証 | 自動テスト名または手動ケースID、前提・入力・期待結果、合否 |
| 実行条件 | 確認した版、ランタイムと依存Mod構成、日時 |
| 証跡 | テスト結果または観測結果の保存先。未実施なら明記 |

網羅性は、次を別々に数える。割合を出す場合は必ず分母となる対象一覧を添える。

- 状態×イベント: 期待結果と根拠が決まったセル／対象セル。前提外は別計上する。
- 条件分岐: ケースを用意した規則／ディシジョンテーブルの規則。
- 時系列: 正常、重複、欠落、逆順、遅延、中断、復帰の各種類にあるケース。
- 不変条件: 正常経路と中断経路の双方で確認するケースを持つ条件／対象条件。
- 実行: 成功／失敗／未実施／仕様未決で判定保留。既存テストとの対応確認と実行成功を分ける。

今回の追加調査ではG01〜G12の現行契約・制限を整理し、G10の境界不備とG13〜G15の終了・reset後の不整合を修正した。T35〜T37の回帰テストを含め4テスト群は成功したが、T行の全分岐とゲーム内ケースは完了扱いにしない。

変更範囲の確認完了は、対象セルに空欄・根拠のない前提外がなく、未決事項が解決または理由付きで保留され、確定仕様に対する確認結果が記録された時とする。保留を含む場合は「全仕様確定」「全ケース成功」とは記載しない。
