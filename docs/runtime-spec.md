# Runtime仕様

## 目的

Runtimeは、ゲーム、SKSE、外部Modとの接続を担当する。外部固有の型、イベント名、スレッド境界を`src`が扱える通知と入出力へ変換し、`src`から要求された結果を外部へ反映する。

Runtimeは手続きの順序、待機時間、計算結果の採否を決めない。アンカーをいつ再計算するかなどの判断は`src`が持ち、個別の計算は`core`が持つ。

## SexLab P+入力

Move Scene時の一時返却と復帰は[Move Scene設計](move-scene-design.md)に従う。Runtimeはプレイヤーの移動入力許可とポーズ状態を提供し、取得不能と入力禁止を区別する。これらの観測と返却の再試行は対応カメラ更新の有無に依存しない。

SexLab P+が送るSKSE `ModCallbackEvent`を購読し、次の未接頭辞イベントをRuntimeの`SceneEvent`へ変換する。

| 外部イベント | Runtime通知 | 用途 |
| --- | --- | --- |
| `AnimationStarting` | `kAnimationStarting` | シーン開始準備 |
| `AnimationStart` | `kAnimationStart` | 初回アニメーションの同期完了 |
| `AnimationChange` | `kAnimationChange` | P+ hotkeyによる実行中アニメーションの変更開始 |
| `ActorsRelocated` | `kActorsRelocated` | 再配置成功。一時中断の復帰待機または構図再評価の契機 |
| `AnimationEnding` | `kAnimationEnding` | シーン終了開始 |
| `AnimationEnd` | `kAnimationEnd` | シーン終了完了 |

`HookAnimationStart`、`HookAnimationChange`、`HookAnimationEnd`、`HookActorsRelocated`も互換入力として同じRuntime通知へ変換する。

`AnimationChange`は変更後の姿勢が利用可能になったことを保証しない。Runtimeは受信直後に通知し、待機や再計算は行わない。

### Scene key

Runtime通知は、送信元QuestのForm IDとP+ thread IDを組み合わせたscene keyを持つ。同一keyを再利用した別シーンに届く旧通知、およびロード後に初めて届く過去シーンの通知は、この情報だけでは識別できない。一致しないkeyとロード前の保留通知を拒否する保証とは分けて扱う。

- 送信元は`SexLab.esm`で定義されたQuestに限定する。プラグインファイル名の大文字小文字は区別しない。
- thread IDは、文字列全体が`int32`範囲内の10進整数である`strArg`を優先する。空白や先頭の`+`は整数文字列として採用しない。負号は受け付ける。
- `strArg`が空または不正な場合は、互換入力として`numArg`を調べる。有限で`int32`範囲内の場合だけ受け付け、小数は最も近い整数へ丸める。ちょうど半分は0から遠い側へ丸める。丸め後も`int32`範囲内でなければ拒否する。
- 両引数が有効でも値が異なる場合は`strArg`を採用する。不正な文字列だけを理由に、正常な数値fallbackを拒否しない。
- 文字列の`2147483647`と`-2147483648`は有効とする。数値の`2147483648`は範囲外として拒否する。
- event名、送信元、thread IDのいずれかが不正な入力は通知しない。

## 参加者と身体中心入力

開始通知を`src`へ渡す前に、Runtimeは送信元QuestのReference Aliasから参加者を収集し、Runtime内部のopaqueなsnapshotとして通知へ付加する。ゲーム固有のhandle型は`src`へ公開しない。

- 同じActorは一度だけ含める。
- プレイヤーを含むかを記録する。
- 最大32人とし、超過時もプレイヤーを優先して保持する。
- 収集とActorHandle化はゲームのメイン更新スレッドで行う。通知元や汎用タスクのワーカーでは実行しない。

`src`からアンカー入力を要求された場合、snapshot内のプレイヤーを取得し、現在の姿勢における腰と胸の中間とActorの水平前方を返す。他の参加者の3D有無、骨格、位置はアンカー入力へ影響させない。snapshot内のプレイヤーActor、腰と胸それぞれの有限で有効な位置、または有効な水平前方を取得できない場合は入力を返さない。

`src`から可視性入力を要求された場合、snapshot内の各参加者について、現在の3D全体を囲むワールド境界の中心を身体中心として一つ返す。Actorまたは有効な身体中心を取得できない参加者は、評価不能として識別できる入力を返す。

アニメーション変更時は参加者snapshotを作り直さず、開始時に保持したsnapshotを使う。参加者構成の変更は現在の対象外とする。

## 実行境界

シーン通知の受理とカメラ構図の継続更新は、別の契機で行う。開始・変更・終了を次のカメラ更新にまとめて受理する契約にはしない。

- シーン通知は、入力の検証と必要な参加者の確認を終えてから手続きへ渡す。
- 継続する構図の生成・追従・反映は、対応カメラ状態の既存処理が完了した後に行う。
- 終了とresetの復帰は通知側からも開始する。カメラ更新の停止だけを理由に終了要求を取り消さない。
- 固定長mailboxの上限・満杯時resetは現行仕様に含めない。
- 対応する状態は通常三人称（ThirdPerson）とAnimated。Freeへの移行はシーンを保持した一時中断とし、その他の対象外への移行は終了・復帰の契機とする。
- active scene中はカメラを取得していなくても、初期入力待ちや診断・時間上限の確認に必要な更新を継続する。

| ポーズ中の動作 | 扱い |
| --- | --- |
| 通常のアンカー追従・定期候補評価 | 停止 |
| Editorの数値previewとその可視性確認 | 継続 |
| Debug切り替えに必要な候補評価、カメラ解放・復帰 | 継続 |
| Debug復帰の間隔・期限 | 実時間で判定 |
| 終了・ロード・reset | 未保存確認やポーズ解除待ちを理由に復帰を妨げない |

ポーズ時間を追従量・定期評価の経過時間へ加えない。ポーズ中に変更通知を受けた場合は、次に更新が許可され、有効な入力を得られる時点で評価する。通常のポーズでは解除後になるが、EditorやDebug切り替えではポーズ中に更新される場合がある。

### 更新連携のライフサイクル

最初のプレイヤー参加scene開始時に一度だけ有効化する。scene終了、ロード、新規ゲーム、camera state変更では連携を再設置・解除しない。初回失敗後も再試行しない。scene外では既存の通常カメラを継続し、SSCの構図計算と出力を行わない。

詳細は[カメラ更新との連携仕様](hook-spec.md)に従う。

## カメラ出力

カメラ制御はSmoothCamの公開APIを通して取得・更新・解放する。

- Runtimeは`src`から渡されたcamera poseとFOV offsetだけを反映する。
- Runtime自身はcamera poseやアンカー位置を決めない。
- FOV offsetは通常の三人称FOVを基準に適用し、実FOVを`10..170 degree`へ制限する。
- 解放時は必要な復帰処理を行ってからSmoothCamへ所有権を返す。
- 所有中に解放する場合はFOV offsetを解除してからSmoothCamへ所有権を返す。
- 所有権を取得していない場合、解放要求は外部状態を変更しない。

有効なcamera poseとFOV offsetを準備できない場合はカメラ制御を取得しない。

## TDMとの連携

True Directional Movementとの連携は任意とし、対応機能が利用可能な場合に開始直後のロックオン解除を扱う。

- 解除要求の受理と、実際にロックオンが外れたことを区別する。ロックオンしていない場合は外部状態を変更しない。
- 解除確認までの一時的な禁止だけを取得する。解除確認、取消または要求受理後2秒の待機上限で、SSCが取得した禁止を返却する。他Modの所有権は奪わない。
- シーン開始通知の処理中にはTDMのロックオン状態を読み書きしない。解除要求はカメラの更新時に行う。
- TDMの状態へのアクセスはTDMが報告する実行スレッドとの一致を確認する。不一致時は解除要求を行わず、その理由を記録する。返却できない所有権は返却待ちとして保持する。
- 終了・ロード・resetで未実行の解除要求を取り消す。取得済みの禁止の返却は、ポーズ中も実行可能な機会に継続する。
- 対応するカメラ更新が停止しても、ゲームのメイン更新が続く間は取得済みの禁止の返却を進める。
- TDMが存在しない、対応機能がない、ロックオンなし、要求拒否、実行スレッドの不一致、解除確認、時間切れ・取消をログで区別する。APIを操作したスレッドIDとTDMが報告するIDを記録する。
- 解除以外の移動制御、headtracking、設定は変更しない。シーン中の再ロックを継続的に禁止せず、終了時に以前の対象へ再ロックしない。

## デバッグ可視化

デバッグモード中は、`src`から渡されたアンカー、プリセット候補位置、可視性ray、身体中心、hit位置、hit法線を現在の画面へ投影して表示する。

- Runtimeはワールド座標を画面上の点と線へ変換するが、位置の決定や結果の採否は行わない。
- アンカーは位置とforward方向を識別できる表示とする。
- ゲーム世界へ参照、一時エフェクト、専用assetを追加しない。
- デバッグモードがOFF、シーン終了、ロード、新規ゲーム、resetのいずれかでは表示しない。
- 表示に失敗した場合はアンカー計算、可視性評価、シーンカメラ手続きを継続する。

## 異常時

- ロード・新規ゲームの前に受理して保留していた通知は、それ以後のシーンへ適用しない。
- 通知処理またはカメラ更新の失敗では復帰とシーン状態の破棄を要求する。復帰が失敗した場合は成功扱いにせず、処理できる機会へ持ち越す。
- 終了・resetの復帰待ちでは旧シーンの評価・構図反映・取得を停止し、ポーズ中も解放を再試行する。処理済みのresetと旧シーンのpreviewは、新しいシーンへ再適用しない。
- 更新連携の有効化に失敗した場合、そのプロセスではシーンカメラを開始しない。
- scene keyの一致、通知の採否、シーンの終了は[シーンカメラ手続き](scene-camera-procedure.md)の規則に従う。

## 現在扱わないもの

- `StageStart`を独立した更新境界として通知すること。
- P+内部の`OnAnimationSynchronized`をhookまたは改変して完了通知を追加すること。
- `AnimationChange`以外の経路でP+内部のactive sceneが変更されたことを推測すること。
- 身体中心の揺れをRuntime側で平滑化すること。Runtimeは補正前の身体中心とポーズ時間を含まない更新間隔を渡し、撮影アンカーの平滑化はアンカー仕様に従う。
