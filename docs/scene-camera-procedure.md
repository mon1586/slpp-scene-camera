# シーンカメラ手続き

状態: **有効候補のA/D切り替えまで実装／ゲーム内確認待ち**

## 目的

Runtimeから受け取るシーンの開始・更新・終了を一つの手続きとして扱い、必要なCore機能を順番に呼び出す。個々の計算方法とゲーム固有の入出力はこの手続きに持ち込まない。

## 基本フロー

```text
Runtimeからシーン開始通知を受け取る
  -> Runtimeへ参加者情報を要求する
  -> 対象シーンなら開始状態を保持する

Runtimeからアニメーション開始通知を受け取る
  -> 次の更新でアンカーを取得するよう予約する

Runtimeからアニメーション変更通知を受け取る
  -> 現在のアンカーを維持したまま指定秒数の遅延の再取得を予約する
  -> 待機中に同じ通知を受けた場合は遅延を数え直す

Runtimeから更新通知を受け取る
  -> Runtimeへ現在のnode情報を要求する
  -> Coreのアンカー計算を呼び出す
  -> 成功したアンカーを固定して保持する
  -> debug可視化が有効ならRuntimeへアンカー表示を要求する
  -> 後続のCore機能を順番に呼び出す
  -> 出力が得られた場合だけRuntimeへ反映を要求する

Runtimeから継続更新を受け取る
  -> 切り替え入力があれば前後の有効候補へカットする
  -> 出力が得られた場合だけRuntimeへ反映を要求する

プリセットEditorを終了する
  -> 編集していたプリセットを含めて候補を再評価する
  -> 編集していた保存済みプリセットが候補に存在すれば可視状態にかかわらず選択を維持する
  -> 編集対象が候補に存在しない場合だけ通常の規則で最初の有効候補を選択する
  -> 選択結果を通常のscene cameraへ反映する

Runtimeからシーン終了通知を受け取る
  -> 現在処理中のシーンと一致するか確認する
  -> 保持している結果と状態を破棄する
  -> Runtimeへ必要な終了処理を伝える
  -> 待機状態へ戻る
```

Runtimeは通知と入出力を担当し、手続き上の判断は行わない。Coreは呼び出された機能だけを計算し、前後の処理順序を知らない。

## アンカーの更新境界

- シーン開始時は、現在のアニメーションのnode transformが反映された後の更新で一度だけ計算する。
- 同じアニメーション中は再計算せず、固定した結果を維持する。
- アニメーション変更時は、P+の`AnimationChange`通知から1秒経過した後の最初の更新で再計算する。
- 1秒の待機中は現在のアンカーを維持する。同じscene keyの`AnimationChange`を再度受けた場合は待機期限を更新する。
- ポーズ中は更新処理を行わない。待機期限がポーズ中に経過した場合は、ポーズ解除後の最初の更新で再計算する。
- シーン終了時は破棄する。

P+の`AnimationChange`は変更開始時に送られ、変更後のnode transformを保証する完了通知ではない。1秒待機はこの制約に対する暫定方針であり、同期完了を保証するものではない。

## 失敗時の扱い

- 対象シーンでない開始通知は何も開始せず終了する。
- 必要なRuntime入力を取得できない場合、その処理結果は無効として手続きを終了する。
- Coreが結果を生成できない場合も同様に終了する。
- debug可視化に失敗した場合は警告だけを記録し、計算結果と手続きを維持する。
- 対応しないscene keyの終了通知は、現在の手続きへ影響させない。
- ロード、新規ゲーム、mailbox異常、watchdogでは保持状態を破棄し、Runtimeへ終了処理を要求する。
- カメラposeがまだ生成されていない段階では、カメラ制御を取得せず、アンカーをカメラ位置として直接出力しない。

## 後続処理

アンカー以降の処理は、同じ手続きで次の順番に行う。

```text
アンカー
  -> プリセット候補
  -> raycast・clearance評価
  -> 有効候補の選択
  -> カメラpose
  -> Runtimeへの出力
```

各段階の計算はCoreの独立した機能とし、手続き側は入力と結果を次段へ渡すだけにする。
