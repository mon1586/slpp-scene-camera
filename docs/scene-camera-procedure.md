# シーンカメラ手続き

状態: **アンカー取得まで実装／後続処理は未実装**

## 目的

Runtimeから受け取るシーンの開始・更新・終了を一つの手続きとして扱い、必要なCore機能を順番に呼び出す。個々の計算方法とゲーム固有の入出力はこの手続きに持ち込まない。

## 基本フロー

```text
Runtimeからシーン開始通知を受け取る
  -> Runtimeへ参加者情報を要求する
  -> 対象シーンなら開始状態を保持する

Runtimeからアニメーション開始通知を受け取る
  -> 次の更新でアンカーを取得するよう予約する

Runtimeから更新通知を受け取る
  -> Runtimeへ現在のnode情報を要求する
  -> Coreのアンカー計算を呼び出す
  -> 成功したアンカーを固定して保持する
  -> 後続のCore機能を順番に呼び出す
  -> 出力が得られた場合だけRuntimeへ反映を要求する

Runtimeからシーン終了通知を受け取る
  -> 現在処理中のシーンと一致するか確認する
  -> 保持している結果と状態を破棄する
  -> Runtimeへ必要な終了処理を伝える
  -> 待機状態へ戻る
```

Runtimeは通知と入出力を担当し、手続き上の判断は行わない。Coreは呼び出された機能だけを計算し、前後の処理順序を知らない。

## アンカーの更新境界

- シーン開始時は、現在のアニメーションのnode transformが反映された後の更新で一度だけ計算する。
- 同じアニメーション中は再計算せず、固定した結果を維持する。
- アニメーション変更時は、変更後のnode transformが反映された後の更新で再計算する。
- シーン終了時は破棄する。

現在はシーン開始と終了の境界だけを接続している。アニメーション変更を検出するRuntime側の境界は未確定であり、未実装である。

## 失敗時の扱い

- 対象シーンでない開始通知は何も開始せず終了する。
- 必要なRuntime入力を取得できない場合、その処理結果は無効として手続きを終了する。
- Coreが結果を生成できない場合も同様に終了する。
- 対応しないscene keyの終了通知は、現在の手続きへ影響させない。
- ロード、新規ゲーム、mailbox異常、watchdogでは保持状態を破棄し、Runtimeへ終了処理を要求する。
- カメラposeがまだ生成されていない段階では、カメラ制御を取得せず、アンカーをカメラ位置として直接出力しない。

## 後続処理

アンカー以降の処理は、実装されるたびに同じ手続きへ次の順番で追加する。

```text
アンカー
  -> プリセット候補
  -> raycast・clearance評価
  -> 有効候補の選択
  -> カメラpose
  -> Runtimeへの出力
```

各段階の計算はCoreの独立した機能とし、手続き側は入力と結果を次段へ渡すだけにする。
