# カメラ更新との連携仕様

状態: **通知と更新の経路を現実装に合わせて整理済み／実接続の境界ケースはゲーム内確認待ち**。

## 目的

SexLab P+の開始・変更・終了を受け取り、対応するカメラ状態の継続更新で選択中の構図を表示する。通知の受理とカメラ構図の継続更新は別の契機である。開始検出はP+のイベント、追従と再評価はカメラ更新を使う。

## 有効化と対応するカメラ状態

- 最初の有効なプレイヤー参加シーンのAnimationStartingまたはAnimationStartで更新連携を一度だけ有効化する。
- DLLロード時とプレイヤー不参加シーンだけでは有効化しない。
- 通常三人称（ThirdPerson）とアニメーション中（Animated）のカメラ状態を対象とする。
- 対象外のカメラ状態へ移った場合は、シーンカメラの終了・復帰を要求する。元の状態へ戻ったことだけでシーンカメラを自動再開しない。
- 有効化後はプロセス終了まで連携を保持する。シーン終了、ロード、新規ゲーム、カメラ状態変更で再設置・解除を行わない。
- 初回の有効化に失敗した場合は、そのプロセスではシーンカメラを使用せず、後続シーンでも再試行しない。DLL全体を終了させる理由にはしない。
- 初回に存在しなかった対象カメラ状態が後から追加される構成には、自動では対応しない。
- 現在の対象はSE/AEであり、VRは対応しない。

## 通知と継続更新の契約

通知の内容・採否は[Runtime仕様](runtime-spec.md)と[シーンカメラ手続き](scene-camera-procedure.md)に従う。

- 開始・変更・終了通知はカメラ更新でまとめて受理する契約ではない。終了とresetを、次のカメラ更新の到来だけに依存させない。
- 通知には固定件数の蓄積上限や「満杯になった時」の動作を設けない。現行の確認ケースにmailbox満杯を含めない。
- 通常の構図生成・追従・反映は、対応カメラ状態の既存処理が完了した後に行う。
- 終了・resetに必要な復帰は通知側からも開始する。通常構図の反映と、終了時の復帰を同じ時点の処理とみなさない。
- ロード前に受理して保留していたシーン通知は、ロード後のシーンへ適用しない。ロード後に初めて届く過去シーンの通知を識別できるとは限らない。
- 同じカメラ更新の中で更新が入れ子になっても、SSCの継続処理を重複させない。
- active scene中はカメラ未取得でも初期入力待ち・診断・時間上限の確認に必要な更新を継続する。
- 対象シーンも保留処理もない場合は、既存のカメラ処理を通常どおり継続し、SSCの構図取得・評価・反映を行わない。

## ポーズとEditor

| 状況 | 動作 |
| --- | --- |
| 通常のポーズ | アンカー追従・定期候補評価を停止 |
| Editor | 確定済みアンカーを維持し、数値previewとその可視性確認を継続 |
| Debug切り替え・復帰試行 | 必要な候補評価・解放・取得を進める。復帰期限は実時間 |
| 終了・ロード・reset | 未保存確認やポーズ解除を待つことを理由に復帰を妨げない |

ポーズ時間を追従量や定期評価の経過時間へ加えない。Editor中に外部から届いた通知は、[シーンカメラ手続き](scene-camera-procedure.md)の採否に従う。ゲーム時間の停止は、すでに発生した通知の消滅を意味しない。

## 他Modとの共存

- 連携の有効化時点で存在する既存カメラ処理を維持する。
- 継続的なSSCの構図反映は、その既存処理の完了後に行う。
- 後から追加されたModがSSCの処理を含む既存の呼び出し順序を維持する場合、その経路を破棄しない。ただしSSCより後に構図を書き換えるModとの最終的な表示は保証しない。
- 既存の連携経路を置換・遮断するModへの追従や、自動的な再設置は行わない。
- カメラ状態の変化を監視することと、連携を再設置することは別である。対象外状態への移行では復帰だけを要求する。
- カメラ所有権はSmoothCamの契約に従う。所有権がなければ他Modの状態を変更しない。

## 失敗と復帰

- 有効化失敗後はシーン通知からカメラ制御を開始しない。
- 通知処理またはSSCの更新処理が失敗した場合は、可能な実行機会でカメラを復帰させ、シーン状態を破棄する。
- 復帰に失敗した場合は成功扱いにせず、再度処理できる機会へ持ち越す。カメラ更新が停止している場合でも、終了要求を取り消さない。
- 終了・resetの復帰待ちでは通常の評価・構図反映を進めず、ポーズ中も解放を再試行する。処理済みのresetが遅れて実行機会を得ても、新しいシーンを終了させない。
- 他Modを含む既存処理自身の例外を、SSCが正常に処理できたと報告しない。
- シーン終了・resetに伴うFOVと所有権の扱いは[Runtime仕様](runtime-spec.md)に従う。

## 確認項目

以下は確認すべき項目であり、すべてが自動テスト済みという意味ではない。

1. プレイヤー不参加シーンでは有効化せず、最初のプレイヤー参加開始で一度だけ有効化する。
2. 二回目以降の開始、ロード、新規ゲーム、カメラ状態変更で追加の有効化を行わない。
3. ThirdPersonとAnimatedで既存処理後に構図が反映される。
4. 対象外カメラ状態への移行で復帰し、通常状態へ戻るだけでは自動取得しない。
5. 通知の受理・終了時の復帰と、継続更新による構図反映をそれぞれ確認できる。
6. ロード前の保留通知が新しいシーンへ適用されない。
7. ポーズ、Editor、Debug復帰で上表の停止・継続が一致する。
8. 終了・reset時にFOVとカメラ制御が残留せず、失敗した復帰が成功として扱われない。
9. 連携失敗後と対象シーン外でも、既存の通常カメラを妨げない。
10. 依存Modと実際のゲーム更新を含む確認を行い、単体テスト・DLLビルドだけで実接続の成功としない。

実装上の経路と今回の調査証跡は[追加調査記録](spec-investigation.md)に分離する。
