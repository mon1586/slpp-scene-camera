# 手動回帰テスト

通常のカメラ、プリセット編集・保存、可視性、Move Scene、デバッグ、アニメーションフィルタをゲーム内で確認するためのチェックリスト。フィルタの実通知経路とUI操作も対象に含む。

この文書の作成時点では、以下の手動テストを実施済みとは扱わない。過去の確認結果は[Move Sceneの記録](move-scene-test.md)と[調査記録](spec-investigation.md)を参照し、今回の実行結果とは分ける。

## 実行と記録

- **毎回**: 基本動作と今回の変更に直結する項目。更新したDLLで毎回実行する。
- **全体**: リリース前、または対応する機能を変更した時に実行する。
- **条件付き**: 対応する構成・再現条件がある時に実行する。条件を満たせなければ未確認とする。
- 各項目は、特記がない限りDebug OFF、Editorを閉じた通常表示から始める。前の項目で変更した条件や設定を引き継がない。
- 結果は`未実施 / PASS / FAIL / 未確認 / 対象外`。対象外には構成上の理由、未確認には再現できなかった条件を記録する。
- カメラの選択はScene toolbarの表示名と構図で確認する。Dashboardで行を選択しただけでは、通常カメラの選択は変わらない。
- Editorを開くと通常のシーン進行は停止する。アニメーションの変更操作はEditorを閉じて行い、変更後の名前・タグを確認する時に開き直す。

## 自動テストとの分担

`build.cmd`で全4スイートが成功することを前提とする。自動化済みの条件表・保存互換性・非同期競合の再現手順は削除した。自動テストの範囲と旧IDの対応は[結合テスト計画](integration-test-plan.md#自動化へ移した確認の記録)を参照する。残ったIDは過去の記録と照合できるよう変更しない。

この表には実機で必要な確認を記載する。自動テスト成功を手動PASSとして記録しない。

## 準備

1. テスト用セーブ・プロファイルを用意する。普段の`Data/SKSE/Plugins/SexlabSceneCamera/presets.json`と、変更する設定ファイルを退避する。削除・不正ファイルのテストは退避後に行う。
2. 正しいDLLがMO2上で有効になっていることを確認する。ゲーム起動後、SSCのロードログを確認する。
3. 壁や家具の少ない場所で、プレイヤー参加シーンを開始できるようにする。遮蔽テスト用に壁・柱・家具のある場所も用意する。
4. 条件なしで、見分けられる構図のプリセットを2件以上用意する。いずれもその場所で可視性条件を満たすことを確認する。
5. アニメーション変更キー、P+の選択UI、ステージ進行、Move Sceneの実際の操作を確認する。キー割り当ては環境の設定に従う。

### フィルタ用のデータ

P+の選択UIから確実に切り替えられる、名前の異なるアニメーションA/Bを選ぶ。SSCのEditorに表示される名前とタグを記録する。A/Bで違うタグもあれば選んでおく。

以下を**X → A用 → B用 → 汎用**の順で保存する。構図はすべて可視性条件を満たし、見分けられるものにする。既存ファイルの順序を変える場合はテスト用コピーを編集してReloadする。

| プリセット表示名 | 名前regex | タグregex | 用途 |
| --- | --- | --- | --- |
| X | `a^` | 空 | 必ず不一致になる先頭候補 |
| A用 | Aの名前を完全一致させる式 | 空 | Aだけで通過 |
| B用 | Bの名前を完全一致させる式 | 空 | Bだけで通過 |
| 汎用 | 空 | 空 | 情報やアニメーションによらず通過 |

名前またはタグ一覧全体を完全一致させる場合は`^...$`を使い、元の文字列に含まれる`. + * ? ( ) [ ] { } ^ $ | \`をエスケープする。タグはスペース区切りの一覧全体へ照合するため、単語タグの存在確認には`\bsitting\b`などを使う。保存順・可視性・正規表現のどれが原因で候補から外れたかを区別できるデータにする。

## ログと判定の扱い

- SSCログ: `Documents/My Games/Skyrim Special Edition/SKSE/SexlabSceneCamera.log`。利用環境により保存先が異なる場合は、実際の場所を実行記録へ記載する。
- P+ログ: 同じSKSEログフォルダの`SexLabUtil.log`。操作経路、変更前後の画面上の名前、時刻と照合する。
- フィルタの確認には`Animation filter committed`のID・名前・タグ数を補助情報として使う。タグの内容はEditor表示で確認する。ログだけで画面上の同期完了と判定しない。
- 旧PoCの`AnimationMetadata timing v3`や`MoveScene probe v1`を今回の成功条件にしない。現行DLLではこれらの観測ログは削除済み。
- クラッシュ・フリーズ・カメラ/FOV/入力の残留は、操作直前からの手順と両ログを保存する。他Modのエラーは発生元も記録し、SSCの原因と即断しない。
- 同じテストで複数条件を変えた場合は、どの条件を確認できたかを分けて記録する。未確認をPASSへまとめない。

## 終了処理と完了条件

1. テスト用のシーン・Editorを終了し、カメラ・FOV・入力が通常状態に戻ったことを確認する。
2. 退避したプリセットと変更した設定・プロファイルを必要に応じて戻す。保存後のログと結果表は残す。
3. 毎回の項目を実行し、FAILと未確認を明示する。全体・条件付きの実施範囲も記録する。
4. 実行済み範囲、未確認の条件、既知不具合を併記して結果を報告する。自動テスト通過を手動テストのPASSの代用にしない。
