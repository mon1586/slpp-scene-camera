# アニメーション情報取得PoC

本PoCは調査記録として残す。追加PoCは行わず、[本実装の設計](animation-filter-design.md)へ移行した。PoCコード・計測ログ出力・専用テストは削除済み。

状態: v3の変更キー経路では初回IDと後続IDが一致。UI経路では実際の変更にAnimationChangeが伴わずStageStartが届くことを確認した。現行の取得対象イベントだけではUI変更を網羅できない。StageStartを契機としたID取得のタイミングは未検証。

## 目的

プリセットへアニメーション名・タグの条件を追加する前に、開始・変更・移動完了の通知を契機とした情報取得のタイミングを検証する。今回の到達点はログでの確認までとする。

v1では5種類のアニメーションについて全14観測で名前・タグを取得し、取得前後のID一致を確認した。各変更通知が必ず実際の切り替えを伴うことや、通知直後の取得が必ず新しい情報であることは、まだ保証しない。

## 期待動作

- プレイヤー参加シーンの開始・アニメーション変更・移動完了を対象に、通知番号、シーン識別、通知種別、観測回、通知の処理待ち時間、取得要求と応答それぞれの経過時間、アニメーションID、表示名、タグ一覧と取得成否を記録する。
- タグは現在のアニメーション全体に付いたタグを対象とする。複数の候補アニメーションに共通するタグや、現在ステージだけのタグとは区別する。
- 各通知の処理時点で最初のID取得を要求する。同じ更新で複数通知を処理しても、それぞれの最初の要求と応答を区別して残す。後続通知の到着だけでは要求済みの結果を捨てない。
- IDは直後、約25・50・100・250・500・1000・2000ミリ秒後の8回を観測する。前のID応答や名前・タグの応答待ちで次のID要求を遅らせない。予定時刻と実際の要求時刻を区別する。ゲーム更新間隔やVM実行待ちによる遅延はあり得る。
- 名前・タグはID観測から分離し、観測されたIDに対する後の情報として記録する。名前・タグが遅れてもIDの変化を確認できる。名前・タグの取得結果を、その取得時点で再生中だったという意味にはしない。
- 各通知の処理から最大5秒で打ち切り、応答がない項目を明示する。これはPoC専用の反復観測であり、製品版での定期取得を決めるものではない。
- 通知番号と観測順から、通知間および同じ通知内のIDを比較できる。同じIDのままの場合は「変化を観測していない」とし、旧値取得や切り替え失敗と断定しない。
- 名前とタグの成功・失敗を別々に確認できる。空の文字列、空のタグ配列、値を取得できない状態を区別する。
- 後続の開始・変更・移動完了で、以前の通知に対する追加ID要求を止める。要求済みの結果は元の通知番号に保持し、どの後続通知で追加要求が止まったかを記録する。
- 終了・ロード・新規ゲームでは観測を打ち切り、取得済みと未完了の情報を区別して残す。その後に返った応答を新しいシーンの値として使用しない。別シーンの変更・終了は現在の観測を置き換えない。
- 負荷を制限するため、同時観測は最大16通知、未解放の取得要求は最大128件とする。超過で観測できなかった通知・取得には理由を残し、完全に観測できた扱いにしない。
- PoC専用の詳細ログ出力を、最初の要求より前やID要求の継続中に挟まない。ログを後から出しても、測定時刻を保持する。ログの一時保持は最大64報告とし、超過分の件数も示す。
- 観測はカメラの構図、選択、プリセット保存内容を変更しない。情報取得の失敗もカメラ動作へ影響させない。

## ゲーム内確認

1. プレイヤー参加シーンを開始し、5秒以上待つ。`AnimationMetadata timing v3`のログでStartingとStartを分けて、最初の要求が両方に残ること、ID・表示名・タグと各取得成否を確認する。
2. 通常の変更キーとP+の選択画面の両方で、名前の異なるアニメーションへ変更し、各回5秒以上待つ。操作経路、画面に表示された変更前後の名前、操作順を記録し、ログの通知・最初と後続のIDに対応付ける。画面上で変わったのに通知がない操作も結果として残す。使えない操作経路は未検証と記録し、イベントだけで全変更を拾えると結論しない。
3. シーンを移動して確定し、3秒以上待つ。移動完了の通知と取得時刻、移動前後のID・名前・タグを比較する。
4. 素早い連続変更、取得中のシーン終了、ロード後の再開始で、各通知の最初の要求、中断理由と取得済み結果が残り、旧観測を新しいシーンの値として表示しないことを確認する。
5. NPCだけのシーンや別シーンの通知で、プレイヤー参加シーンの観測が置き換わらないことを確認する。
6. 通常のカメラ表示、A/D切替、Editor、終了時の復帰が従来どおり動作することを確認する。

取得成功は実ゲームのログで判断する。ビルド成功や取得用宣言の存在だけでは成功としない。取得元がない、呼び出せない、通知後の値が追従しない場合も、このPoCの調査結果として記録する。

要求から応答までのどこかで値が読み取られるため、応答時刻をP+内部の切り替え時刻とはみなさない。このPoCはイベント経由の取得結果が後続観測と一致するかを確かめるもので、内部の代入時刻や画面上の姿勢同期完了を直接測定するものではない。途中で中断された観測や試していない操作経路まで、イベント1回で十分と結論しない。

既存ログやVMの負荷による測定への影響は残る。観測した範囲で値が一致しても、競合が起きないことの証明とはしない。通知のない操作はイベント起点のPoCだけでは検出できないため、上記の画面表示との照合を必須とする。
